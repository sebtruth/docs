Phase 1
01 Prerequisites

  • Comfortable using a terminal

    You should be able to run basic terminal commands — navigating directories, copying and pasting, etc.

  • GitLab account active

    You have access to gitlab.real-digital.de using your company credentials.

  • Claude Code installed

    Claude Code is set up on your machine and ready to use.

  • Claude Skill plugin installed

    Install the plugin from the internal marketplace: gitlab.real-digital.de/public-repos/agent-plugin-marketplace

  • SSH key configured for GitLab

    An SSH key is added to your GitLab profile so that git clone works without authentication issues.

Phase 2
02 Align with your team – project preparation

  • Suitable project identified with your team

    Discuss with your teams which projects are ready to use — onecommand support is required.

  • Service names and Git repositories identified

    Use the service name (e.g. seller-portal.frontend.app) to determine which repository to clone. Naming conventions are documented in the Handbook.

    💡 The service name tells you directly where to start. Refer to the Handbook for the official naming schema.

  • Use case for the workshop defined

    Your use case is clearly scoped and specific enough to be implemented directly in Claude Code during the session.

Phase 3
03 During the workshop – steps in Claude Code
ℹ️ These steps will be completed live during the workshop — no action required beforehand. They are listed here for reference and orientation.

  • Clone the repository

    Clone the relevant Git repository via SSH:

    $ git clone git@gitlab.real-digital.de:YOUR_PROJECT/repo-name.git copy

  • Deploy the repository to the sandbox

    Sync the cloned repository to the sandbox environment:

    $ sandbox deploy__sync copy
    ✅ Once deployed, the frontend is accessible via the browser URL in your development environment.
🔄 Need additional services? Simply repeat the steps in Phase 3 — clone the repository, deploy, done.
